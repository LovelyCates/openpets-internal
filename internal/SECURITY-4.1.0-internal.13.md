# Internal .13 安全修复说明

本版从 Internal .12 的依赖、导入和本地数据审计修复而来。Windows 与 macOS
共用相同实现；发布附件中的构建记录用于核对源码及公共载荷一致性。

## 修复范围

- 固定 Electron 45.3.3、Sharp 0.35.5、Undici 7.30.2、get-windows 10.0.0，
  更新 MCP SDK 及构建工具链。移除可选 peer 的自动安装，避免将外部 OpenClaw、
  Pi 宿主及其依赖无谓地打入桌面包；现有集成及宿主安装方式保留。
- 对宠物文件先做有大小限制的 WebP 容器检查，再进入原生解码；V1 也须完整
  解码。拒绝伪装成 WebP 的其他图片、损坏压缩数据、异常尺寸及超预算动画。
  保留有效多帧 V1；已检查的 3,738 份目录素材均符合限制，14/59/18 帧原始
  样本已在 Sharp 0.35.5 下完整解码。
- 媒体、ZIP 和目录导入在文件系统访问前拒绝 UNC、混合分隔符网络路径和
  Windows 设备命名空间。Discovery 文件采用有上限的描述符读取、身份检查，
  拒绝叶节点及直接父目录的符号链接；POSIX 检查所有者及私有权限。
- Provider 配置整体加密，额外 HTTP 请求头和隔离的旧配置也包含在同一密文
  中。助手历史加密保存在本地，继续执行原来的保留条数、时长和容量限制。
  这些历史属于应用助手，不是 OpenCode 会话全文。
- 加密使用真实系统后端。macOS 不再启用测试钥匙串，Windows 使用系统
  加密；Linux 拒绝 `basic_text`。钥匙串不可用、文件损坏、版本不支持或迁移
  写入失败时保留原文件并拒绝写入，不降级为明文、不以空配置覆盖原数据。
- 日志在运行中串行轮转：当前文件和两份保留文件各不超过 2 MiB；限制单条
  长度、递归结构和待写队列，退出前刷新已接受日志。POSIX 使用私有权限，
  拒绝日志符号链接，API Key、敏感字段及 token 文本在输出前脱敏。

Electron 的测试钥匙串行为已与[该版本原始实现](https://github.com/electron/electron/blob/v45.3.3/patches/chromium/revert_oscrypt_remove_sync_backend.patch)
及 [safeStorage 实现](https://github.com/electron/electron/blob/v45.3.3/shell/browser/api/electron_api_safe_storage.cc)
核对。如果曾在旧版 macOS 中保存 API 凭据，应更换相应服务的密钥；仅重新
加密无法撤销旧密钥。无法解密的旧记录保留供恢复，不自动尝试弱密钥解密。

## 验证与边界

2026-11-17 的完整锁文件公告扫描为 0 个已知漏洞，包含生产和开发依赖。
这是当时公告数据库与锁文件的匹配结果，不能证明不存在未知漏洞。
完整桌面检查、OpenCode/client 检查、44 项 pet-format 测试及文档构建通过；
最后的恢复副本加密改动另经重新编译和隐私回归复核。macOS 原生 Electron
45.3.3 在未启用 mock/basic 参数时完成合成数据加解密，公开测试密钥无法
解开其密文；实际 Keychain 服务命名未单独核实，未查询或删除共享项目。
实际打包依赖、原生模块、安装包完整性及双端公共载荷另按发布流程检查。

行为回归覆盖图片伪装/损坏、导入、发现文件、访问前网络路径拒绝、配置和
历史加密迁移、故障保留、日志轮转与脱敏；真实网络策略保持关闭。测试中的
网络服务及加密适配器均为隔离夹具，不接触用户凭据、会话或配置目录。

Windows ACL、系统映射盘符和已挂载网络卷仍受操作系统策略管理；路径字面
检查不等于隔离所有网络存储。加密保护静态文件，不隔离同一登录用户已经
运行的恶意程序。损坏或无法迁移的旧明文文件可能仍保留，需恢复钥匙串或
修复文件后迁移，避免以销毁恢复数据来掩盖问题。

恶意软件引擎检查与本说明分开记录。以本版实际安装包的扫描报告为准，
检测命中、超时和未完成均不能写成“全部通过”。本版仍无企业发行证书：
Windows 未签名，macOS 为 ad-hoc 签名、未公证。
